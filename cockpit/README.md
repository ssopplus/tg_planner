# dev-cockpit

Локальный наблюдатель за всеми сессиями Claude Code на машине: CLI, VS Code и Desktop.

```bash
pnpm cockpit             # http://127.0.0.1:4317
PORT=5000 pnpm cockpit
```

Зависимостей нет, нужен Node 22+ и `claude` в PATH. Работает только локально: читает `~/.claude` и git на этой машине,
поэтому живёт в репозитории tg-planer отдельной папкой и в Next.js-приложение и деплой на Vercel не входит
(`.mjs` не попадает в `tsconfig`). Свои имена и проекты сессий — в `cockpit/data/` (в `.gitignore`).

## Автозапуск

```bash
bash cockpit/install-launchd.sh             # launchd-агент local.dev-cockpit: старт при входе, перезапуск при падении
bash cockpit/install-launchd.sh uninstall   # убрать
tail -f ~/Library/Logs/dev-cockpit.log
```

После правок `server.mjs` перезапуск — `launchctl kickstart -k gui/$(id -u)/local.dev-cockpit`
(`index.html` читается на каждый запрос, для него хватит перезагрузки страницы).

## Откуда данные

| Что | Источник |
|---|---|
| Список сессий и статус (работает / ждёт / простаивает, чего ждёт) | `claude agents --json`, раз в 2 с |
| Заголовок, последний промпт и ответ, лента действий, правленые файлы | транскрипт `~/.claude/projects/*/<sessionId>.jsonl`, дочитывается с последнего смещения |
| Репозитории сессии | git-корни файлов из Edit/Write и каталогов из `cd …` / `git -C …` в Bash |
| Изменения | `git status`, коммиты ветки и `git diff` от базы. База — ближайшая из `origin/HEAD`, `origin/master`, `origin/main`, `origin/turbo_main` |

## Экраны

- **Доска** — полосы по проектам, колонки «Ждёт меня / Работает / Готово, посмотреть / Простаивает».
  «Готово, посмотреть» — сессия что-то сделала после того, как ты её последний раз открывал (отметки в localStorage).
  Проект, где всё простаивает, сворачивается в строку.
- **Входящие** — кто ждёт ответа, кто закончил и ещё не просмотрен, кто работает.
- **Задача** (вкладка на странице сессии и «☑ 8/9» на карточке) — заметка задачи, которую ведёт скилл `/start-task`:
  план «Что нужно сделать» с отметками и ворклог «Сделано / Осталось / Блокеры» по сессиям, запись этой сессии раскрыта.
  Заметка ищется в `Документация/Проекты` по заголовку записи `### дата · сессия <8 символов id>` или по `issue: КЛЮЧ`;
  каталог перечитывается раз в 30 с, файлы — только изменившиеся.
- **Сессия** — переписка (Markdown, действия Claude свёрнуты в группы, вопросы AskUserQuestion видны сразу),
  справа вкладки «Свойства», «Изменения» (git, diff по клику), «Действия».

## Ответы сессиям

Запросы разрешений и вопросы Claude (`AskUserQuestion`) приходят через глобальные HTTP-хуки в `~/.claude/settings.json`:

```json
"hooks": {
  "PermissionRequest": [{ "hooks": [{ "type": "http", "url": "http://127.0.0.1:4317/hooks/PermissionRequest", "timeout": 600 }] }]
}
```

- Хук держит запрос до 590 с, пока не придёт решение из cockpit или Telegram. Нативный диалог VS Code при этом показывается
  как обычно, и побеждает первый ответ. Ответ в VS Code соединение хука не закрывает: cockpit замечает его по транскрипту
  (у вызова с тем же инструментом и входом появился результат) и снимает карточку.
- Если cockpit не запущен или не успел, сессия просто остаётся с нативным диалогом.
- Свободный текст из поля под перепиской уходит в межсессионный сокет сессии (`messagingSocketPath` из
  `~/.claude/sessions/<pid>.json`). Claude получает его как реплику соседней сессии с пометкой `[из dev-cockpit]`.

## Mini App планировщика

Cockpit сам ходит в `POST /api/cockpit/sync` tg-planer: шлёт снимок сессий, ожидающие запросы и итоги закрытых, а в ответ
получает решения из Mini App. Входящих соединений на машину нет. Включается файлом `data/sync.json`:

```json
{ "url": "https://tg-planner.vercel.app/api/cockpit/sync", "secret": "<COCKPIT_SECRET из Vercel>" }
```

Подхватывается без перезапуска. Пока есть ожидающие запросы, синк идёт раз в 3 с, в покое — только при изменении снимка
и раз в минуту как пульс. Значок 📱 в шапке показывает, что синк включён (✕ — последняя попытка упала, причина в подсказке).

- Вся работа — в разделе «Сессии» Mini App: статусы по проектам, последняя реплика Claude, запросы с полным входом и
  кнопками «Разрешить / Всегда / Отклонить» или вариантами ответа. Число ожидающих запросов — счётчиком на вкладке.
- В чат бота ничего не пишется: от десятка сессий это превращалось в ленту, которую невозможно читать.
- В облако уходят имя, проект, статус, последняя реплика Claude и входы запросов. Переписка и diff остаются на машине.
  Пароли, токены, `Bearer`, пароли в URL и `-p<пароль>` маскируются перед отправкой. Запросы хранятся 7 дней.

## Имена и проекты

Переименовать уже запущенную сессию снаружи Claude Code нельзя (только `/rename` внутри неё или `Ctrl+R` в `claude agents`).
Поэтому имена живут в `data/meta.json`:
- кнопка «✨ Имена» придумывает имена сессиям с автоименем `claude-xx` (`claude -p --model haiku` без инструментов, MCP и настроек; ~8 с на сессию, по 4 параллельно);
- имя правится кликом по заголовку сессии; «Копировать /rename» даёт команду, чтобы перенести имя в сам Claude Code.

Проект определяется так: ручной выбор → очередь ключа задачи → основной репозиторий (тот, где больше всего правок; worktree сводится к основному репо).
Соответствия очередей и репозиториев проектам — в `projects.json`.

Сервер слушает только `127.0.0.1`. Отдаёт git только по тем репозиториям, которые встретились в сессиях.
Формат jsonl внутренний и может поменяться с версией Claude Code. Если разбор сломается, следующий шаг — HTTP-хуки.

Переменные окружения: `PORT`, `CLAUDE_BIN`, `CLAUDE_CONFIG_DIR`, `VAULT_DIR`.
