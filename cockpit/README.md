# dev-cockpit

Локальный наблюдатель за всеми сессиями Claude Code на машине: CLI, VS Code и Desktop.

```bash
pnpm cockpit             # http://127.0.0.1:4317
PORT=5000 pnpm cockpit
```

Зависимостей нет, нужен Node 22+ и `claude` в PATH. Работает только локально: читает `~/.claude` и git на этой машине,
поэтому живёт в репозитории tg-planer отдельной папкой и в Next.js-приложение и деплой на Vercel не входит
(`.mjs` не попадает в `tsconfig`). Свои имена и проекты сессий — в `cockpit/data/` (в `.gitignore`).

## Автозапуск

```bash
bash cockpit/install-launchd.sh             # launchd-агент local.dev-cockpit: старт при входе, перезапуск при падении
bash cockpit/install-launchd.sh uninstall   # убрать
tail -f ~/Library/Logs/dev-cockpit.log
```

После правок `server.mjs` перезапуск — `launchctl kickstart -k gui/$(id -u)/local.dev-cockpit`
(`index.html` читается на каждый запрос, для него хватит перезагрузки страницы).

## Откуда данные

| Что | Источник |
|---|---|
| Список сессий и статус (работает / ждёт / простаивает, чего ждёт) | `claude agents --json`, раз в 2 с |
| Заголовок, последний промпт и ответ, лента действий, правленые файлы | транскрипт `~/.claude/projects/*/<sessionId>.jsonl`, дочитывается с последнего смещения |
| Репозитории сессии | git-корни файлов из Edit/Write и каталогов из `cd …` / `git -C …` в Bash |
| Изменения | `git status`, коммиты ветки и `git diff` от базы. База — ближайшая из `origin/HEAD`, `origin/master`, `origin/main`, `origin/turbo_main` |

## Экраны

- **Доска** — полосы по проектам, колонки «Ждёт меня / Работает / Готово, посмотреть / Простаивает».
  «Готово, посмотреть» — сессия что-то сделала после того, как ты её последний раз открывал (отметки в localStorage).
  Проект, где всё простаивает, сворачивается в строку.
- **Входящие** — кто ждёт ответа, кто закончил и ещё не просмотрен, кто работает.
- **Статус задачи** на каждой карточке, в том числе в компактных строках: статус в Яндекс Трекере (синий — в работе,
  фиолетовый — тестирование/ревью, зелёный — закрыта) и план «☑ 8/9». Трекер читается только на чтение пачкой
  `POST /v2/issues/_search` раз в 2 мин; токен — `TRACKER_TOKEN`/`TRACKER_ORG_ID` из env или из `~/Разработка/.mcp.json`.
- **Задача** (вкладка на странице сессии и «☑ 8/9» на карточке) — заметка задачи, которую ведёт скилл `/start-task`:
  план «Что нужно сделать» с отметками и ворклог «Сделано / Осталось / Блокеры» по сессиям, запись этой сессии раскрыта.
  Заметка ищется в `Документация/Проекты` по заголовку записи `### дата · сессия <8 символов id>` или по `issue: КЛЮЧ`;
  каталог перечитывается раз в 30 с, файлы — только изменившиеся.
- **План** — очерёдность задач Трекера по проектам. Проекты выбираются чипами (несколько сразу), у каждого слева
  «План» — мой порядок задач, справа «Задачи проекта» — открытые тикеты его очередей из `projects.json`
  («Мои» — где я исполнитель плюс заведённые мной без исполнителя, «Все открытые» — вся очередь, до 100 штук; поиск в шапке фильтрует список).
  Над списком — фильтры по статусу и типу (чипы с числом задач), «с сессией», «с планом ☑» и сортировка: «В работе
  сверху», по обновлению, созданию, статусу, приоритету или номеру, со стрелкой направления. Выбор свой у каждого
  проекта и живёт в localStorage. Задачи в статусе «Закрыт»/«Отменено» без резолюции тоже считаются закрытыми.
  На строке — статус в Трекере, план заметки «☑ 8/9» с полосой и следующим пунктом, сессии, которые ведут задачу
  (клик открывает сессию), клик по названию — описание из Трекера. «+ в план», перетаскивание (в нужное место плана,
  внутри плана — порядок, из плана в список — убрать), ↑ ↓ ✕, ▶ — вкладка Claude в VS Code с `/start-task КЛЮЧ`.
  Порядок хранится в `data/plan.json`, Трекер только читается (`POST /v2/issues/_search` по запросу очереди,
  кэш 1 мин, ↻ — перечитать). Задачи плана, выпавшие из выборки (закрыты, чужие), дочитываются по ключам.
- **Сессия** — переписка (Markdown, действия Claude свёрнуты в группы, вопросы AskUserQuestion видны сразу),
  справа вкладки «Свойства», «Изменения» (git, diff по клику), «Действия».

## Ответы сессиям

Запросы разрешений и вопросы Claude (`AskUserQuestion`) приходят через глобальные HTTP-хуки в `~/.claude/settings.json`:

```json
"hooks": {
  "PermissionRequest": [{ "hooks": [{ "type": "http", "url": "http://127.0.0.1:4317/hooks/PermissionRequest", "timeout": 600 }] }]
}
```

- Хук держит запрос до 590 с, пока не придёт решение из cockpit или Telegram. Нативный диалог VS Code при этом показывается
  как обычно, и побеждает первый ответ. Ответ в VS Code соединение хука не закрывает: cockpit замечает его по транскрипту
  (у вызова с тем же инструментом и входом появился результат) и снимает карточку.
- Если cockpit не запущен или не успел, сессия просто остаётся с нативным диалогом.
- Режим сессии (Manual / Edit automatically / Plan / Auto) виден в шапке сессии и в «Свойствах». Поменять его снаружи
  можно только вместе с ответом на запрос: в карточке запроса выбрать «режим после ответа», cockpit добавит к решению
  `updatedPermissions: [{type: "setMode", mode, destination: "session"}]`. Bypass и dontAsk из cockpit не включаются.
  То же в Mini App: режим приходит в снимке (`permissionMode`), выбор «Режим после ответа» в карточке запроса
  уходит в решение полем `setMode` и доходит до сессии через синк.
  Переключить режим простаивающей сессии внешнего входа у Claude Code нет — только Remote Control в приложении Claude.
- Свободный текст из поля под перепиской уходит в межсессионный сокет сессии (`messagingSocketPath` из
  `~/.claude/sessions/<pid>.json`). Claude получает его как реплику соседней сессии с пометкой `[из dev-cockpit]`.

## Mini App планировщика

Cockpit сам ходит в `POST /api/cockpit/sync` tg-planer: шлёт снимок сессий, ожидающие запросы и итоги закрытых, а в ответ
получает решения из Mini App. Входящих соединений на машину нет. Включается файлом `data/sync.json`:

```json
{ "url": "https://tg-planner.vercel.app/api/cockpit/sync", "secret": "<COCKPIT_SECRET из Vercel>" }
```

Подхватывается без перезапуска. Значок 📱 в шапке показывает, что синк включён (✕ — последняя попытка упала, причина в подсказке).

- Вся работа — в разделе «Сессии» Mini App: статусы по проектам, последняя реплика Claude, запросы с полным входом и
  кнопками «Разрешить / Всегда / Отклонить» или вариантами ответа. Число ожидающих запросов — счётчиком на вкладке.
- В чат бота ничего не пишется: от десятка сессий это превращалось в ленту, которую невозможно читать.
- По нажатию на сессию в Mini App раскрываются её задачи (статус в Трекере, план, запись ворклога) и поле «Написать в
  сессию». Текст ложится командой в `cockpit_commands`, cockpit забирает её ближайшим синком и отправляет в сокет сессии.
- К сообщению можно приложить до 4 скринов («Скрин»): Mini App сжимает их в JPEG (длинная сторона до 2000 px) и кладёт
  в `payload.images` команды. Cockpit сохраняет их в `data/uploads/` (хранятся 7 дней) и дописывает в сообщение пути —
  Claude открывает их через Read. После итога команды синк вычищает картинки из БД, остаётся `imageCount`.
- Раздел «Сессии» — доска, как в cockpit: «Ждёт меня · Работает · Готово, посмотреть · Простаивает» друг под другом
  («Простаивает» свёрнута) или группы «По проектам». «Готово, посмотреть» — сессия что-то сделала после просмотра
  (за неделю); просмотренность хранится в localStorage телефона, отметка — «✓ просмотрено», «отметить все» или открыть
  переписку. На карточке — статус задачи, полоса плана с первым невыполненным пунктом, запрос или причина ожидания,
  последняя реплика. Поиск и множественный выбор проектов, фильтры тоже в localStorage.
- На карточке задачи Трекера в Mini App — «Взять в работу в Claude»: cockpit запускает в `~/Разработка`
  (`COCKPIT_TASK_CWD`) фоновую сессию `claude --bg --name КЛЮЧ "/start-task КЛЮЧ"`. Нужен CLI ≥ 2.1.306 и один раз
  в терминале в этом каталоге: `claude` → принять доверие к папке и «Enable selected» на вопросе про MCP-серверы
  проекта (`.mcp.json`). VS Code этот вопрос не задаёт, а фоновая сессия на нём встаёт (`state: blocked` в
  `claude agents --json`, pid нет) — cockpit показывает её «ждёт» с подсказкой `claude attach <id>`; подключиться
  можно из любого терминала, в том числе встроенного в VS Code. Сообщения в фоновую сессию идут по регистрации
  в `~/.claude/sessions/`, найденной по id сессии.
- Фоновую сессию расширение VS Code не открывает, пока жив её процесс («That session is running in the background»).
  «Перенести в VS Code» (страница сессии в cockpit и в Mini App) делает `claude stop <id>` и открывает её через
  `vscode://anthropic.claude-code/open?session=<sessionId>` — переписка сохраняется.
- Запрос разрешения cockpit держит до ответа, но не дольше `timeout` хука PermissionRequest в
  `~/.claude/settings.json` (cockpit по умолчанию готов ждать сутки, `HOOK_HOLD_MS`). При 600 с фоновая сессия через
  10 минут без ответа застревает на вопросе в невидимом терминале — поэтому timeout стоит поднять до 86400.
- «Открыть в VS Code на Маке» (там же) и «▶ Задача в VS Code» на доске cockpit открывают вкладку Claude через
  uri-хендлер расширения `vscode://anthropic.claude-code/open?prompt=/start-task КЛЮЧ`. Расширение текст только
  подставляет, отправить — Enter в VS Code; поэтому с телефона задачу начинает фоновая сессия.
- Синк: снимок — при изменении и раз в 5 мин, между ними лёгкий опрос раз в 10 с за решениями и командами, при
  ожидающих запросах — раз в 3 с.

- «Открыть переписку» — страница сессии в Mini App: последние ~100 сообщений (Markdown, действия Claude одной строкой
  без входа и вывода), запросы, план задачи и поле «Написать». Переписка уходит с машины только пока страница открыта:
  Mini App раз в 3 с ставит `watched_at` в `cockpit_transcripts`, cockpit видит это в ответе синка и шлёт хвост при
  изменении. Копия одна, перезаписывается, удаляется через час после закрытия экрана.
- В разделе «Трекер» Mini App на карточке задачи видно, что её ведёт сессия Claude: статус сессии и план «☑ 5/7».

### Remote Control

Для полноценной работы внутри сессии с телефона — официальный Remote Control Claude Code: в VS Code
«Enable Remote Control for all sessions» (или `remoteControlAtStartup: true` в `~/.claude/settings.json`). Сессии
появляются в приложении Claude (вкладка Code): переписка, промпты от твоего имени, разрешения, вопросы, push.
Mini App остаётся пультом: обзор всех сессий, статусы задач, запросы, короткие реплики и запуск задач.
- В облако уходят имя, проект, статус, последняя реплика Claude и входы запросов. Переписка и diff остаются на машине.
  Пароли, токены, `Bearer`, пароли в URL и `-p<пароль>` маскируются перед отправкой. Запросы хранятся 7 дней.

## Имена и проекты

Переименовать уже запущенную сессию снаружи Claude Code нельзя (только `/rename` внутри неё или `Ctrl+R` в `claude agents`).
Поэтому имена живут в `data/meta.json`:
- кнопка «✨ Имена» придумывает имена сессиям с автоименем `claude-xx` (`claude -p --model haiku` без инструментов, MCP и настроек; ~8 с на сессию, по 4 параллельно);
- имя правится кликом по заголовку сессии; «Копировать /rename» даёт команду, чтобы перенести имя в сам Claude Code.

Проект определяется так: ручной выбор → очередь ключа задачи → основной репозиторий (тот, где больше всего правок; worktree сводится к основному репо).
Соответствия очередей и репозиториев проектам — в `projects.json`.

Сервер слушает только `127.0.0.1`. Отдаёт git только по тем репозиториям, которые встретились в сессиях.
Формат jsonl внутренний и может поменяться с версией Claude Code. Если разбор сломается, следующий шаг — HTTP-хуки.

Переменные окружения: `PORT`, `CLAUDE_BIN`, `CLAUDE_CONFIG_DIR`, `VAULT_DIR`.
